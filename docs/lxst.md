# DotLXST reference audit

## Status and scope

**Partial, independently authored interoperability implementation.** `DotLXST`
implements bounded stream envelopes, portable raw audio, native Opus/Codec2 ABI
adapters, asynchronous stream sessions and device-independent telephony.
`rnphone` provides a partial executable with Linux PulseAudio capture/playback.
Full upstream API, processing, utility and platform parity is **not complete**.

The project is experimental, AI-assisted and not an official or endorsed LXST
implementation.

### Dependencies and platform evidence

The Python packaging manifest requires Python 3.11+, RNS 1.0.4+, LXMF 0.9.3+,
NumPy 2.3.4+, pycodec2 4.1.0+, CFFI 2.0.0+, and audioop-lts on Python 3.13+.
These are upstream minimum requirements, not permission to move this repository's
RNS/LXMF pins. Opus uses bundled PyOgg bindings and native codec libraries;
Codec2 uses pycodec2. The package can build a native filter extension and skips
that extension build on Windows. Device backends exist for Linux, Windows,
macOS and Android. Hardware peripherals additionally depend on appropriate
GPIO/I2C modules and physical devices.

No .NET codec strategy or native-library redistribution decision has been made.
Any future native interop must isolate codec handles, expose explicit ownership,
declare library versions/licensing, and demonstrate trimming/NativeAOT behavior.
No target OS, real codec bitstream, microphone/speaker, GPIO/I2C device or
RAK/RNode transport has been verified for DotLXST.

## Architecture and ownership

`StreamPacket` uses DotReticulum's bounded, reflection-free MessagePack codec.
Its envelope cap is 65,535 bytes with separate depth/value/container limits.
Real sessions also enforce the actual link MDU; there is no invented
fragmentation. `ReticulumStreamTransport` has a bounded receive queue (32 by
default), explicit overflow accounting/error reporting and no link ownership.
`StreamSession` serializes sends and processes ingress on one async worker,
switches decoder by discriminator, and runs without observers. A failing sink or
observer is reported without disabling other observers. Every concurrent
disposer waits for the same cleanup completion.

`TelephoneEndpoint` registers only on explicit `Start`, owns a single call,
identifies over real links, exposes audio independently of devices, and accepts a
caller authorization function. Router, identity and sink remain caller-owned.
`IAudioSource`, `IAudioSink`, `IAudioCodec` and `IAudioCodecFactory` are hardware
and native-library boundaries. `rnphone` implements Linux I/O with cancellable
`parec`/`pacat` subprocesses and obtains devices from `pactl`. It never starts
audio for help, version or configuration errors.

No DSP/mixer or file-container implementation is implied by these interfaces.
The CLI does not currently reproduce upstream AGC, band-pass filtering, easing,
dial/ring tones, hardware peripherals or all persistence/configuration behavior.

### Native codec and platform matrix

No native libraries are redistributed by this repository. Users supply libopus
(BSD-licensed upstream project) and libcodec2 (follow the installed package's
LGPL and component notices). ABI handles and library references have explicit
disposal; native operations are serialized, including Codec2's process-global
excitation state. Native module loading uses no runtime code generation.

| Environment | Evidence |
|---|---|
| Windows x64 | Managed build and deterministic/unit/lifecycle tests; native codec DLLs and device audio not verified |
| Ubuntu x64 under WSL | libopus 1.6.1 and libcodec2 1.2.0 vectors; real stream/telephone interop; NativeAOT executable and virtual PulseAudio process flow |
| Physical audio hardware | Unverified; tests use isolated silent/generated virtual devices, never the desktop microphone |
| macOS, Android, other architectures | Unverified; no device implementation or support claim |

`rnphone` is therefore a Linux-audio executable, not a verified cross-platform
audio product. Linux identity files are created with owner read/write only;
filesystems that cannot enforce this (for example default WSL DrvFS mounts)
are rejected. On Windows, inherited ACLs require operator review.

## Evidence and reproduction

`tests/DotLXST.Tests/GenerateLxstVectors.py` executes the real pinned Raw, Opus,
Codec2, Packetizer and SignallingReceiver APIs. It records source digests,
actual module location, Python/NumPy/pycodec2 versions, libopus version and the
pycodec2 native-library digest in `Fixtures/lxst-vectors.json`. The packet-byte
observation temporarily captures `RNS.Packet.send` at the transport boundary;
it does not alter LXST packing or implement a substitute reference codec.
This capture-only vector mechanism is **not live network evidence**.

Codec2's mono NumPy input path in the pinned reference raises a dimensionality
error in pycodec2; vectors and live stream sends exercise its working stereo
input path, which selects a mono channel. No reference source shim is installed.
Codec2's excitation PRNG is process-global: the vector test keeps the module
loaded across the complete sequence, matching Python's lifetime. Both the
distribution-installed library and pycodec2's separately installed native
library passed the strict sample comparisons.

Recorded results:

- Windows deterministic/unit suite: **18 passed**.
- WSL full LXST suite against the actual primary-release checkout:
  **29 passed, zero skipped**, twice consecutively with all four opt-ins enabled.
- Telephone lifecycle cases include a blocked sink proving that a second
  disposer cannot finish early, continued service after authorization/observer
  exceptions, and cancellation of an abandoned path lookup without disrupting
  the next call.
- Linux NativeAOT publish with both warning-as-error properties: **passed**;
  published `--help`: **passed**.
- Native rnphone Pester process acceptance: **3 passed, zero skipped**:
  CLI/error behavior; explicit unsupported-hardware rejection; calls in both
  directions, encoder/decoder/device-process paths, teardown, protected identity
  and restart stability.

Live stream cases use actual unmodified Python Packetizer/LinkSource and real
Reticulum TCP links in three topologies: direct; through a .NET transport; and
through a Python transport. Each exercises raw/Opus/Codec2 in both directions,
mid-stream codec replacement, signalling, teardown, targeted 20% packet loss
and 5 ms delay in each direction, and delivery after impairments are removed.
The expected lost frames stay lost: LXST has no made-up retry protocol.

Live telephony cases use actual unmodified Python `Telephone`, with both Python
and .NET initiating. They verify setup states, medium-quality Opus audio in both
directions, a generated 440 Hz signal observed at Python's isolated output
monitor, Python-to-.NET decoded frames and teardown. This is virtual device
evidence, not a listening test or proof of physical microphone/speaker quality.
Telephone calls through transport hops, exhaustive profiles/policy/timeout
matrices, hardware I/O and long-duration recovery remain unverified.

### Stack gap

`Link.Send(data, createReceipt: false)` returns null both on successful
receiptless enqueue and on failure. `ReticulumStreamTransport` can reject an
inactive link and oversize frame but cannot reliably reproduce Python
`Packetizer.transmit_failure` for a saturated stack outbound queue using the
current public API. No LXST-specific submodule workaround is used. This gap is not hidden behind
invented delivery receipts.
