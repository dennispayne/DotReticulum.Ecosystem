# DotLXST reference audit

## Status and scope

**Partial, independently authored interoperability implementation.** `DotLXST`
implements bounded stream envelopes, portable raw audio, native Opus/Codec2 ABI
adapters, asynchronous stream sessions and device-independent telephony.
`rnphone` provides a partial executable with Linux PulseAudio capture/playback,
an original Windows WinMM backend and Linux GPIO/I2C hardware-provider wiring.
Full upstream API, processing, utility and platform parity is **not complete**.

The project is experimental, AI-assisted and not an official or endorsed LXST
implementation.

Telephone defaults differ from utility defaults. `Telephone` uses 60-second
ring, 70-second wait and 5-second connect timeouts. `ReticulumTelephone` supplies
30-second ring, 60-second wait and a separate 10-second path lookup limit.
These are source observations, not executed behavioral evidence.

The endpoint now executes the primary caller-policy/profile APIs for reference
vectors. Its total outgoing wait budget includes path discovery, with a separate
deadline for reaching ringing. Incoming manual rejection sends status `1` before
teardown; a ring timeout does not. Manual ring timeout is not applied to delayed
auto-answer calls. Unidentified incoming links have a bounded connect deadline,
an explicit defensive .NET extension rather than a claimed Python timeout.
The mutable `ConnectTimeout` property follows executed `set_connect_timeout`
observations: zero and negative values are retained and make the next outgoing
deadline expire immediately; changing the property does not rewrite a deadline
already captured by an outgoing call. The defensive incoming-link timeout is
separate and retains its construction-time option.
The source `set_announce_interval()` stores `announce_interval`, but `__jobs`
reads the `ANNOUNCE_INTERVAL` constant; that mutable setter has no demonstrated
effect. The .NET configurable interval is an explicit extension.

Telephony exposes eight profiles: ultra-low/very-low/low bandwidth; medium/high/
maximum quality; low/ultra-low latency. Their nominal frame durations are
400/320/200/60/60/60/20/10 ms respectively. The bandwidth profiles select Codec2
700C/1600/3200; the remaining profiles select Opus. The default is medium quality.
Codec2 aggregation durations are not Opus frame durations.

Endpoint transmit audio passes through the independently verified
`BandPassFilter(250, 8500)` and, by default, `AutomaticGainControl(-15)`, then
reference mixer gain/mute and final `[-1, 1]` clipping. The reference permits
the 8500 Hz cutoff even with 8 kHz input; vectors cover that non-Nyquist-limited
behavior. Gain follows the actual mixer's `10 ** (gain / 10)` multiplier, not
an assumed `gain / 20` amplitude convention. Receive gain/mute affects both
the external sink and audio observers. Mute resets on teardown; gains persist.
The AGC setter affects filter construction for subsequent calls. No physical
capture/playback quality claim follows from these headless processing tests.

### Dependencies and platform evidence

The Python packaging manifest requires Python 3.11+, RNS 1.0.4+, LXMF 0.9.3+,
NumPy 2.3.4+, pycodec2 4.1.0+, CFFI 2.0.0+, and audioop-lts on Python 3.13+.
These are upstream minimum requirements, not permission to move this repository's
RNS/LXMF pins. Opus uses bundled PyOgg bindings and native codec libraries;
Codec2 uses pycodec2. The package can build a native filter extension and skips
that extension build on Windows. Device backends exist for Linux, Windows,
macOS and Android. Hardware peripherals additionally depend on appropriate
GPIO/I2C modules and physical devices.

The .NET native ABI strategy and tested matrix are described below. Physical
microphone/speaker quality, GPIO/I2C and RAK/RNode transport remain unverified.

## Architecture and ownership

`StreamPacket` uses DotReticulum's bounded, reflection-free MessagePack codec.
Its envelope cap is 65,535 bytes with separate depth/value/container limits.
Real sessions also enforce the actual link MDU; there is no invented
fragmentation. `ReticulumStreamTransport` has a bounded receive queue (32 by
default), explicit overflow accounting/error reporting and no link ownership.
`StreamSession` serializes sends and processes ingress on one async worker,
switches decoder by discriminator, and runs without observers. A failing sink or
observer is reported without disabling other observers. Every concurrent
disposer waits for the same cleanup completion.

`TelephoneEndpoint` registers only on explicit `Start`, owns a single call,
identifies over real links, exposes audio independently of devices, and accepts a
caller authorization function. Router, identity and sink remain caller-owned.
`IAudioSource`, `IAudioSink`, `IAudioCodec` and `IAudioCodecFactory` are hardware
and native-library boundaries. `rnphone` implements Linux I/O with cancellable
`parec`/`pacat` subprocesses and obtains devices from `pactl`. It never starts
audio for help, version or configuration errors.

`IAudioDeviceBackend` supplies typed input/output enumeration and defaults plus
asynchronously owned `IAudioCapture`/`IAudioPlayback` leases. `DeviceAudioSource`
enforces a single active reader, configurable linear gain, cancellation and
lease cleanup; `DeviceAudioSink` serializes writes, reopens on format/device
changes and recovers by releasing a failed output lease before the next write.
Disposing either wrapper releases leases, not the caller-owned backend.
Device formats are bounded to 384 kHz, 64 channels and one second per frame;
providers may support a narrower set. These are explicit resource limits.
These original interfaces replace Python backend-object shapes rather than
claiming Python class-layout compatibility.

`DotLXST.Audio` supplies a separately tested managed processor, mixer, generator
and pipeline layer; the stream/session interfaces do not silently apply it.
Endpoint AGC/band-pass processing is shared by the CLI. Hardware software is
wired behind explicit providers; physical peripherals and all
persistence/configuration behavior are not claimed verified. Configured ringtone playback is
implemented without redistributing the upstream asset.

`PhoneConfiguration` reads quote-aware comma values and inline comments. Reload
validates a replacement before swapping authorization and selected devices; a
failed reload leaves the running process and prior settings intact. This atomic
replacement is a deliberate .NET behavior: primary `reload_config` retains and
merges existing phonebook/allow/block dictionaries and lists. Unknown settings
and malformed allow/block policy hashes are rejected rather than silently
ignored. Malformed phonebook rows are skipped with contextual warnings, matching
the primary's usable-entry behavior. Empty trailing list components and extra
phonebook columns are tolerated. Duplicate numeric aliases select the last menu
entry, matching the actual primary's menu-key overwrite.
`AudioCaptureEnvelope` reproduces the actual LineSource frame-delayed gain ramp
and discarded threshold-crossing skip frame. Its vectors execute the unmodified
ingest job using a disclosed synthetic recorder and deterministic clock, not a
hardware capture claim. CLI capture applies the observed 75 ms skip and initial
225 ms easing; subsequent profile/device restarts use zero easing.
`BufferedAudioSink` has the observed six-frame drop-oldest bound, advisory
`CanReceive` threshold below three queued frames, late-frame dropping, channel
truncation and restart after starvation. The CLI resamples incoming audio to
48 kHz before enqueueing; mono is retained. The sink does not own the supplied
output. Its portable clock waits eight frame durations for starvation rather
than claiming identical OS scheduling or hardware latency.
The native acceptance checks self-entry exclusion and identity/config persistence
across process restart. No history/ignored/allowed file implementation is invented.

### Native codec and platform matrix

No native libraries are redistributed by this repository. Users supply libopus
(BSD-licensed upstream project) and libcodec2 (follow the installed package's
LGPL and component notices). ABI handles and library references have explicit
disposal; native operations are serialized, including Codec2's process-global
excitation state. Native module loading uses no runtime code generation.
Linux Codec2 first loads the verified runtime SONAME `libcodec2.so.1.2`, with
an unversioned fallback; a development-package symlink is not required.

Ogg file operations additionally use independently installed BSD-licensed Xiph
libopusfile and libopusenc. The original C ABI wrappers were checked against
their public headers and actual reference bindings; no Ogg muxer/demuxer source
is ported. `OpusFileSource` decodes mono/stereo at 48 kHz into bounded frames
(1–1000 ms), supports looping and optional pacing, and rejects channel-changing
chains. `OpusFileSink` opens/truncates the supplied path, requires the selected
profile's sample rate/channels, bounds input to one second per frame, pads short
frames to the first frame's length, appends the reference's ten silence frames,
and finalizes on async disposal. Native containers interoperate; byte-identical
Ogg page serialization is not claimed. `FilePlayer` and `FileRecorder` do not own
their external sink/source. Stop and every concurrent disposer wait for in-flight
I/O and file finalization. A recorder path change only applies while stopped.
Executing primary `FileRecorder.set_output_path` leaves the actual sink path
unchanged and creates a separate name-mangled shadow attribute; the effective
.NET setter is an explicit extension. Default recorder capture filters/easing
are source configuration, not silently imposed on caller-provided frames.
Cancellation is observed between bounded native file operations; a blocking
filesystem/native call itself is not forcibly interrupted.

`TelephoneToneSource` composes the independently verified managed tone generator
with primary's 382 Hz frequency, 3.14159 ms easing, 0.04 linear gain and observed
ringback/busy cadence. `GenerateTelephoneToneVectors.py` executes the actual
cadence jobs with disclosed synthetic audio/clock/thread boundaries; mutable
generator gain transitions separately execute actual `ToneSource.__generate`.
The CLI routes ringback/busy audio to its own selected-speaker process, applies
receive gain/mute and cancels stale playback on another call or shutdown.
Unlike Python's blocking busy job before its final callback, the device-independent
endpoint reports Busy/Rejected promptly and the CLI plays the bounded tone
asynchronously after that outcome. That callback timing difference is explicit.

### Operating-system providers

`Hardware.LinuxDigitalPins` uses the Linux GPIO character-device v2 API
([kernel contract](https://docs.kernel.org/userspace-api/gpio/chardev.html),
introduced in Linux 5.10). GPIO numbers are **chip line offsets**, not header
pin numbers. The default `/dev/gpiochip0` must actually correspond to the
intended board controller; `DOTLXST_GPIOCHIP` selects another path. The provider
holds one owned `SafeHandle` per requested line, reconfigures rather than
releasing/reacquiring lines during scans, applies explicit pull bias and
serializes operations against disposal.

`LinuxI2cByteBus` uses the documented
[`i2c-dev` interface](https://docs.kernel.org/i2c/dev-interface.html):
non-forcing `I2C_SLAVE` selection followed by a single-byte write. The default
`/dev/i2c-1` can be replaced with `DOTLXST_I2C_DEVICE`. Bus numbering and GPIO
chip identity are operator-selected, not discovered or assumed from a board
name. Missing devices, permission errors, unsupported ioctl operations and
short writes throw contextual errors; there is no simulation/fallback success.
The native providers accept little-endian Linux x64/arm64; only x64 error paths
and compiled ABI layouts have executed here, not arm64 or successful peripheral
I/O. Cancellation/disposal waits for synchronous kernel I/O rather than claiming
to forcibly interrupt a blocked kernel call.

`rnphone` wires `gpio_4x4`, an optional `keypad_hook_pin`, and `i2c_lcd1602`
before identity creation, then owns scanner, bus and display cleanup. Software
controls reproduce primary numeric alias entry/editing, answer/reject/hangup,
hook transitions and 15-second idle display sleep. A 64-event bounded queue
reports overflow; input is capped at 256 digits as an explicit defensive
extension. Hardware setting changes require process restart instead of silently
opening duplicate primary driver instances during reload. Call-duration display
formatting is original .NET text, not a byte-identical Python terminal claim.

PCM16 backend, **not** a translation of the reference SoundCard/WASAPI bindings.

### Reticulum adapter guarantees and ownership

The adapter uses public `Link.TrySend` and the exclusive
`Link.RegisterPacketReceiver` lease at tested stack commit `b8a1cc5`.
`TrySend` distinguishes a rejected local enqueue from successful receiptless
enqueue; it does not invent delivery receipts or network reliability.
The short core ingress receiver copies into a bounded queue and updates counters
only. Decoding, signalling and error observers run outside core ingress.

Registration atomically rejects an existing foreign receiver or another adapter.
The stack's legacy setter cannot replace or clear an active lease. Disposal
releases only this adapter's registration without owning or tearing down the
link; repeated concurrent disposal cannot clear a later owner's receiver.
An already captured ingress callback may finish after lease removal and safely
encounters the completed bounded queue.

Concurrent legacy `PacketReceived` observers are unsuitable for deterministic
setup ingestion. Python RNS also dispatches those observers on independent
threads: no ordering guarantee for its public observers is claimed.
The explicit ordered core ingress API fixes the observed native telephone
Established-before-Connecting callback race without altering LXST packets.
The Python-free `NativeStandalone` Pester flow passed ten consecutive runs
concurrently with the full live suite after adopting this API. Each run uses two real native rnphone processes and
verifies both encode/network/decode/playback paths, profile reconfiguration,

no Python/reference checkout or live flag is required.
Virtual daemons have unique runtime/state paths and are denied access to the
shared session D-Bus singleton, preventing concurrent `org.PulseAudio1`
registration collisions without changing desktop audio. Stale canceled capture
tasks cannot hang up a replacement call when teardown closes their old session.
